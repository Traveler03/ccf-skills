# Figure Policy

Use this file before extracting, embedding, or describing figures from a paper.

## Default

For methodology figures, always capture:

- Figure number.
- Page number.
- Caption.
- Source paper link.
- Chinese explanation of each important module.
- Why this figure matters for the paper's method.

## Public Repository Rule

If the reading note will be committed to a public repository:

- Do not embed full copyrighted paper figures by default.
- Prefer figure metadata, a source link, and a Chinese explanation.
- Embed the figure only when the figure is clearly licensed for reuse, is generated by the user, or the user explicitly authorizes committing it.

## Private Local Note Rule

If the note is private/local and the user asks to include the methodology figure:

- Render the relevant PDF page or crop the figure when feasible.
- Save the image near the note using a clear name, such as `fig-method-overview.png`.
- Include the image with Markdown syntax and an adjacent source note.
- Do not crop unrelated figures or long copyrighted sections.

## Figure Explanation Checklist

Explain:

- What enters the pipeline.
- What each module does.
- What is optimized, searched, trained, retrieved, or verified.
- What exits the pipeline.
- Which part corresponds to the paper's core insight.
- Which part is only engineering support.
